# Практическая работа №6: Spring Security (Вариант 1 — Телевизор)

Веб-приложение для управления каталогом товаров (телевизоров) на базе **Spring MVC**, **Spring Security** и шаблонизатора **FreeMarker** с хранением доменных данных и учетных записей пользователей в СУБД **PostgreSQL** через **Spring JDBC**.

---

## 1. Описание функционала и выполненные требования

В проект практической работы №5 интегрирована комплексная система аутентификации и авторизации:

1. **Страница регистрации (`/register`)**:
   * Пользователь самостоятельно вводит логин и пароль.
   * Данные проверяются на стороне сервера (валидация длины логина/пароля и проверка уникальности логина).
   * Запись сохраняется в базу данных с автоматическим присвоением роли `ROLE_USER`.
2. **Собственная форма аутентификации (`/login`)**:
   * Форма создана программно на шаблонизаторе FreeMarker (не является сгенерированной по умолчанию страницей Spring Security).
   * Поддерживает отображение уведомлений о неверном вводе данных, успешном выходе из системы и завершении регистрации.
3. **Разграничение ролей**:
   * **`ROLE_ADMIN` (Администратор)**: полный доступ ко всем функциям системы (просмотр, добавление, редактирование, удаление, поиск).
   * **`ROLE_USER` (Пользователь)**: доступ только к чтению (просмотр каталога и поиск по ценовому критерию).
4. **Безопасность на уровне запросов (URL Intercepting)**:
   * Маршруты `/login` и `/register` открыты для всех (`permitAll`).
   * Маршруты модификации данных (`/tvs/add`, `/tvs/edit`, `/tvs/delete`) защищены правилом `hasRole('ROLE_ADMIN')`. Прямой переход по URL для обычного пользователя блокируется ошибкой `403 Access Denied`.
   * Каталог и поиск защищены правилом `hasAnyRole('ROLE_USER', 'ROLE_ADMIN')`.
5. **Хранение пользователей в базе данных**:
   * Учетные записи и роли хранятся в таблице `public.users`.
   * Пароли хэшируются с использованием стойкого алгоритма **BCrypt** (`BCryptPasswordEncoder`).
   * Аутентификация выполняется через механизм Spring `<jdbc-user-service>`.
6. **Выход из приложения (`logout`)**:
   * Реализован сброс пользовательской сессии по POST-запросу на `/logout` с последующим редиректом на форму входа.
7. **Безопасность на уровне представлений (UI)**:
   * В шаблонах подключена библиотека тегов Spring Security (`JspTaglibs`).
   * В шапке отображается персонализированное приветствие с именем текущего пользователя (`<@security.authentication property="principal.username" />`) и бейджем роли.
   * Элементы управления модификацией данных (кнопка добавления, ссылки «Редактировать» и «Удалить» в таблице) обернуты в тег `<@security.authorize access="hasRole('ROLE_ADMIN')">` и скрыты для роли `User`.

```text
tv-web-app/
├── pom.xml                                   # Сборщик Maven: зависимости Spring MVC, Security, JDBC, FreeMarker

    └── main/
        ├── java/
        │   ├── controllers/
        │   │   ├── AuthController.java       # Обработка входа (/login) и регистрации (/register)
        │   │   ├── HomeController.java       # Маршрутизация главной страницы (/)
        │   │   └── TvController.java         # Управление каталогом (/tvs/**)
        │   ├── dao/
        │   │   ├── TvDao.java                # Слой доступа к данным таблицы tv
        │   │   └── UserDao.java              # Слой доступа к данным таблицы users
        │   └── models/
        │       ├── Tv.java                   # Модель телевизора с аннотациями валидации
        │       └── User.java                 # Модель учетной записи пользователя
        ├── resources/
        │   ├── application.properties        # Параметры подключения к локальной СУБД PostgreSQL
        │   └── config/
        │       ├── applicationContextMVC.xml # Конфигурация Spring MVC и FreeMarker
        │       └── security.xml              # Конфигурация Spring Security и JDBC Authentication
        └── webapp/
            └── WEB-INF/
                ├── views/                    # Шаблоны представлений FreeMarker (.ftl)
                │   ├── index.ftl             # Главная страница с проверкой ролей
                │   ├── login.ftl             # Программная форма аутентификации
                │   ├── register.ftl          # Форма регистрации нового пользователя
                │   ├── tv_add.ftl            # Форма добавления телевизора
                │   ├── tv_delete.ftl         # Страница подтверждения удаления
                │   ├── tv_edit.ftl           # Форма редактирования записи
                │   ├── tv_list.ftl           # Каталог с контекстными кнопками по ролям
                │   └── tv_search.ftl         # Поиск товаров по бюджету
                └── web.xml                   # Дескриптор развертывания с DelegatingFilterProxy
```

## 3. База данных и предустановленные пользователи

### Конфигурация подключения (`src/main/resources/application.properties`)
```properties
dataSource.driverClassName=org.postgresql.Driver
dataSource.url=jdbc:postgresql://localhost:5432/postgres
dataSource.username=postgres
dataSource.password=postgres
```

### Автоматическая инициализация таблиц
При первом запуске приложения бины `TvDao` и `UserDao` автоматически создают схему `public` и необходимые таблицы:
* `public.tv` — таблица товаров (id, brand, model, screen_technology, screen_diagonal, price).
* `public.users` — таблица пользователей:
  ```sql
  CREATE TABLE IF NOT EXISTS public.users (
      id SERIAL PRIMARY KEY,
      username VARCHAR(100) UNIQUE NOT NULL,
      password VARCHAR(255) NOT NULL,
      role VARCHAR(50) NOT NULL,
      enabled BOOLEAN NOT NULL DEFAULT TRUE
  );
  ```

### Предустановленные тестовые аккаунты
При старте в базу автоматически добавляются две стандартные учетные записи с захэшированными BCrypt-паролями:

| Логин | Пароль | Назначенная роль | Доступные привилегии |
| :--- | :--- | :--- | :--- |
| **`admin`** | `admin` | `ROLE_ADMIN` | Полный CRUD (просмотр, добавление, редактирование, удаление, поиск) |
| **`user`** | `user` | `ROLE_USER` | Только чтение (просмотр каталога, поиск по цене) |

## 4. Системные требования

* **Java Development Kit (JDK):** версия 17 или выше
* **Apache Maven:** версия 3.6+
* **Контейнер сервлетов:** Apache Tomcat 9.x
* **СУБД PostgreSQL:** локальный экземпляр, запущенный на порту `5432`

## 5. Инструкция по сборке и развертыванию

### 1. Компиляция и сборка WAR-пакета
В корневой директории проекта выполните команду:
```bash
mvn clean package
```
В результате успешной компиляции в папке `target/` будет сформирован архив `tv-web-app.war`.

### 2. Развертывание в Apache Tomcat
1. Скопируйте файл `target/tv-web-app.war` в каталог `webapps/` вашего сервера Tomcat.
2. Перейдите в каталог `bin/` сервера Tomcat и запустите его:
   * **Windows:**
     ```cmd
     startup.bat
     ```
   * **Linux / macOS:**
     ```bash
     ./startup.sh
     ```

### 3. Точка входа в приложение
После инициализации сервера откройте браузер по адресу:
```text
http://localhost:8080/tv-web-app/
```

## 6. Примеры работы и сценарии проверки

### Сценарий 1. Аутентификация администратора
1. Перейдите по адресу `http://localhost:8080/tv-web-app/` — произойдет автоматический редирект на `/login`.
2. Введите учетные данные: логин `admin`, пароль `admin`.
3. Откроется главная страница. В шапке отображается: `Здравствуйте, admin! [Администратор]`.
4. В меню отображаются все пункты, включая «Добавить новый телевизор (только Admin)».
5. В таблице каталога (`/tvs`) отображается колонка «Действия» со ссылками на редактирование и удаление товаров, а также кнопка добавления новой позиции.

### Сценарий 2. Регистрация нового пользователя
1. На странице `/login` нажмите на ссылку «Нет аккаунта? Зарегистрироваться» (`/register`).
2. Введите желаемый логин (от 3 символов) и пароль (от 4 символов).
3. Нажмите кнопку «Зарегистрироваться». Система сохранит пользователя в таблицу `public.users` с ролью `ROLE_USER` и перенаправит на страницу логина с сообщением об успехе.

### Сценарий 3. Проверка ограничений обычного пользователя
1. Войдите под учетной записью `user` (пароль `user`) или под только что зарегистрированным аккаунтом.
2. В шапке отображается: `Здравствуйте, user! [Пользователь]`.
3. На главной странице отсутствует пункт добавления записи.
4. В каталоге (`/tvs`) скрыты кнопка «Добавить товар» и колонка «Действия» (ссылки редактирования и удаления не отрисовываются).
5. При попытке вручную ввести в адресную строку `http://localhost:8080/tv-web-app/tvs/add` сервер возвращает HTTP-статус **403 Access Denied** (доступ запрещен на уровне `security.xml`).

### Сценарий 4. Выход из системы (Logout)
1. Нажмите кнопку «Выйти» в правом верхнем углу страницы.
2. Произойдет отправка POST-запроса на `/logout`, сессия завершится, и откроется форма авторизации с сообщением: *«Вы успешно вышли из системы»*.
