# Отчет по практической работе №8: Spring JMS

**Тема:** Асинхронный обмен сообщениями в Spring (Java Message Service и брокер Apache ActiveMQ)

**Цель работы:** ознакомиться с механизмом JMS в Spring.

**Базовая работа:** проект выполнен путем модификации **практической работы №5** (веб-приложение на базе Spring MVC, шаблонизатора FreeMarker и СУБД PostgreSQL, вариант «Телевизор»).

---

## 1. Постановка задачи и выполненные требования

В рамках модернизации веб-приложения из практической работы №5 реализован следующий функционал (пункты 1–5*):

1. **Настройка очереди сообщений администратора:** сконфигурировано подключение к брокеру сообщений Apache ActiveMQ (`tcp://localhost:61616`) и настроена очередь `tv.admin.queue` по модели «точка-точка» (Point-to-Point).


2. **Уведомления об операциях модификации данных:** при выполнении операций добавления, редактирования или удаления телевизора через веб-формы приложение формирует сериализуемый объект уведомления `Alert` и асинхронно отправляет его в очередь брокера с помощью `JmsTemplate`.


3. **Извлечение административных сообщений:** разработано консольное приложение `JmsReceiverApp`, которое подключается к брокеру сообщений из терминала, извлекает накопленные уведомления методом `jmsTemplate.receive()` и выводит подробный журнал событий.


4. **Оформление покупки товара:** в пользовательском интерфейсе (в таблице каталога, на странице поиска и на форме редактирования) добавлена кнопка «Купить», отправляющая в брокер сообщений уведомление о том, какой именно телевизор приобрел пользователь.


5. **Учет купленных товаров (пункт 5*):** после отправки информации о покупке в брокер сообщений товар помечается в базе данных как купленный (`sold = TRUE`) и автоматически скрывается из общего каталога доступных товаров.

## 2. Архитектура и стек технологий

* **Язык программирования:** Java 17.


* **Фреймворк:** Spring Framework 5.3.10 (`spring-core`, `spring-context`, `spring-web`, `spring-webmvc`, `spring-jdbc`, `spring-jms`).


* **Брокер сообщений:** Apache ActiveMQ Classic (`activemq-spring` 5.16.3, протокол OpenWire на порту `61616`).


* **Представления (View):** шаблонизатор Apache FreeMarker 2.3.31.


* **Валидация данных:** Bean Validation API (JSR-380) и Hibernate Validator 6.2.0.


* **СУБД:** PostgreSQL (доступ через `JdbcTemplate`).


* **Контейнер сервлетов и сборка:** Apache Tomcat 9.x, Apache Maven.



### Схема асинхронного взаимодействия через JMS

```text
[ Веб-браузер ] ──(POST /tvs/add, /edit, /delete, /buy)──> [ TvController ]
                                                                 │
                                   ┌─────────────────────────────┴─────────────────────────────┐
                                   ▼                                                           ▼
                            [ TvDao (JDBC) ]                                       [ AlertService (JmsTemplate) ]
                                   │                                                           │
                                   ▼                                                           ▼ (send ObjectMessage)
                            [ PostgreSQL ]                                       [ Брокер ActiveMQ (tv.admin.queue) ]
                         (Таблица public.tv)                                                   │
                                                                                               ▼ (receive ObjectMessage)
                                                                                 [ Консольный приемник JmsReceiverApp ]

```

### Ключевые изменения относительно практической работы №5

* **Модель данных (`models.Tv`):** класс реализует интерфейс `java.io.Serializable` для возможности упаковки в `ObjectMessage` при передаче через JMS. Добавлено булево свойство `sold` для фиксации факта продажи товара.


* **Сущность уведомления (`jms.Alert`):** сериализуемый Java-класс, инкапсулирующий тип операции (`ДОБАВЛЕНИЕ`, `РЕДАКТИРОВАНИЕ`, `УДАЛЕНИЕ`, `ПОКУПКА`), текстовое описание, отметку времени и сам объект `Tv`.


* **Сервис сообщений (`jms.AlertService`, `jms.AlertServiceImpl`):** использует `JmsTemplate` и `MessageCreator` для создания `ObjectMessage` и отправки его в очередь `tv.admin.queue`, а также метод `receive()` для синхронного извлечения сообщений из очереди.


* **Конфигурация JMS (`config/jmsConfig.xml`):** объявляет бин `ActiveMQConnectionFactory` (`brokerURL = "tcp://localhost:61616"`, `trustAllPackages = "true"`), бин `JmsTemplate` с очередью по умолчанию `tv.admin.queue` и таймаутом чтения `2000` мс, а также бин `alertService`.


* **Слой DAO (`dao.TvDao`):** при инициализации добавляет в таблицу `public.tv` столбец `sold BOOLEAN NOT NULL DEFAULT FALSE`, фильтрует список в `findAll()` и `findByPriceLessThanEqual()` по условию `WHERE sold = FALSE`, а в методе `markAsSold(int id)` переводит флаг `sold` в `TRUE`.


* **Контроллер (`controllers.TvController`):** в методы `POST /tvs/add`, `POST /tvs/edit` и `POST /tvs/delete` добавлен вызов `alertService.sendAlert(...)`. Добавлен метод `POST /tvs/buy`, который сначала отправляет сообщение о покупке в очередь брокера, а затем вызывает `tvDao.markAsSold(id)`.

## 4. Инструкция по сборке, развертыванию и свертыванию из командной строки

### 4.1. Подготовка и запуск зависимостей (PostgreSQL и ActiveMQ)

1. **Запуск СУБД PostgreSQL** (в терминале от имени администратора):
```powershell
net start postgresql-x64-18

```


Проверка доступности БД:
```powershell
psql -U postgres -h 127.0.0.1 -c "\l"

```


2. **Установка и запуск брокера сообщений Apache ActiveMQ:**
* Скачайте архив Apache ActiveMQ Classic с официального сайта (`[https://activemq.apache.org/components/classic/download/](https://activemq.apache.org/components/classic/download/)`) и распакуйте его.


* Перейдите в директорию исполняемых файлов брокера (для 64-разрядной ОС Windows) и запустите брокер:


```powershell
cd C:\programming\activemq\bin\win64
.\activemq.bat

```


* Брокер запустится и откроет TCP-порт `61616` для JMS-соединений и веб-консоль управления по адресу `http://localhost:8161/admin` (логин: `admin`, пароль: `admin`).





### 4.2. Сборка и развертывание (установка) веб-приложения

1. Перейдите в корневую директорию проекта `tv-web-app` и выполните сборку WAR-архива с помощью Maven:


```powershell
mvn clean package

```


2. Скопируйте сгенерированный архив `target\tv-web-app.war` в директорию `webapps` контейнера сервлетов Apache Tomcat и запустите сервер:


```powershell
copy .\target\tv-web-app.war C:\programming\tomcat\apache-tomcat-9.0.122\webapps\
C:\programming\tomcat\apache-tomcat-9.0.122\bin\startup.bat

```


3. Веб-приложение будет развернуто по адресу: `http://localhost:8080/tv-web-app/`.



### 4.3. Свертывание (удаление) приложения и остановка зависимостей

1. **Остановка сервера Apache Tomcat и удаление веб-приложения:**
```powershell
C:\programming\tomcat\apache-tomcat-9.0.122\bin\shutdown.bat
del C:\programming\tomcat\apache-tomcat-9.0.122\webapps\tv-web-app.war
rmdir /s /q C:\programming\tomcat\apache-tomcat-9.0.122\webapps\tv-web-app

```


2. **Очистка артефактов сборки проекта:**
```powershell
mvn clean

```


3. **Остановка брокера сообщений ActiveMQ:**
В окне консоли запущенного ActiveMQ нажмите сочетание клавиш `Ctrl + C`.


4. **Остановка службы PostgreSQL (при необходимости):**
```powershell
net stop postgresql-x64-18

```

## 5. Инструкция по использованию и демонстрация работы

### Шаг 1. Выполнение операций в веб-интерфейсе

1. Откройте в браузере страницу каталога `http://localhost:8080/tv-web-app/tvs`.


2. **Добавление товара:** перейдите по ссылке «+ Добавить товар» (`/tvs/add`), заполните поля (`Xiaomi`, `Dry`, `OLED`, `55.0`, `55000.00`) и нажмите «Сохранить». Товар появится в таблице, а в очередь `tv.admin.queue` уйдет уведомление с типом `ДОБАВЛЕНИЕ`.


3. **Редактирование товара:** нажмите «Редактировать» напротив записи с `ID = 8`, измените бренд на `dkk` и сохраните изменения. В очередь отправится уведомление `РЕДАКТИРОВАНИЕ`.


4. **Покупка товара:** нажмите зеленую кнопку **«Купить»** напротив телевизора `Xiaomi Dry` (`ID = 15`).


* В брокер сообщений отправляется уведомление `ПОКУПКА` с данными выбранного телевизора.


* В базе данных записи `ID = 15` присваивается статус `sold = TRUE`, и она исчезает из списка доступных для покупки товаров.


* На экране выводится сообщение: *«Заявка на покупку отправлена в брокер сообщений! Товар помечен как купленный»*.




5. **Удаление товара:** нажмите «Удалить» напротив записи `ID = 8` и подтвердите удаление. В очередь отправится уведомление `УДАЛЕНИЕ`.

## 6. Вывод

В ходе выполнения практической работы веб-приложение на базе Spring MVC было интегрировано с брокером сообщений Apache ActiveMQ посредством модуля Spring JMS и шаблона `JmsTemplate`. Реализована асинхронная отправка сериализованных объектных уведомлений (`ObjectMessage`) в очередь администратора при добавлении, редактировании, удалении и покупке товаров, обеспечено скрытие купленных позиций из каталога и продемонстрировано извлечение сообщений внешним консольным приемником.
