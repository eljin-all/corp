# Отчет по практической работе №5: Spring MVC

**Тема:** Разработка веб-приложения на базе Spring MVC (Вариант 1 — Телевизор)

**Цель работы:** ознакомиться с шаблоном MVC в Spring и особенностями его применения при проектировании веб-приложений.

---

## 1. Постановка задачи и требования

В рамках работы консольное приложение из практической работы №4 переработано в многостраничное веб-приложение со следующей функциональностью:

1. **Главная страница (`/`)** — приветствие и навигационные ссылки на все разделы.


2. **Просмотр таблицы записей (`/tvs`)** — табличный вывод всех объектов из базы данных.


3. **Добавление новой записи (`/tvs/add`)** — форма ввода с валидацией.


4. **Редактирование записи (`/tvs/edit`)** — форма модификации существующего объекта.


5. **Удаление записи (`/tvs/delete`)** — страница подтверждения и удаление по первичному ключу.


6. **Выборка по критерию (`/tvs/search`)** — поиск телевизоров с ценой не выше заданной.


7. **Серверная валидация входных данных** — проверка корректности ввода (не менее двух полей) с выводом диагностических сообщений.



---

## 2. Архитектура и стек технологий

Приложение построено в соответствии с архитектурой «Модель 2» на основе шаблона MVC:

* **Язык программирования:** Java 17.
* **Бэкенд-фреймворк:** Spring Framework 5.3 (Spring Context, Spring Web, Spring Web MVC, Spring JDBC).


* **Шаблонизатор:** Apache FreeMarker 2.3.


* **Валидация:** Bean Validation API (JSR-380) и Hibernate Validator.


* **База данных:** PostgreSQL (локальный порт `5432`, доступ через `JdbcTemplate`).
* **Контейнер сервлетов:** Apache Tomcat 9.x.

## 3. Описание компонентов системы

### Модель данных (`models.Tv`)

Сущность содержит 6 атрибутов, снабженных аннотациями Bean Validation:

* `id` (`Integer`) — идентификатор записи (`PRIMARY KEY`).
* `brand` (`String`) — марка устройства; валидация `@NotEmpty(message = "Поле бренда не должно быть пустым")`.


* `model` (`String`) — модель устройства; валидация `@NotEmpty(message = "Поле модели не должно быть пустым")`.


* `screenTechnology` (`String`) — технология экрана; валидация `@NotEmpty`.
* `screenDiagonal` (`Double`) — диагональ экрана; валидация `@NotNull`, `@Positive(message = "Диагональ должна быть положительным числом")`.
* `price` (`Double`) — стоимость в рублях; валидация `@NotNull`, `@Positive(message = "Цена должна быть больше нуля")`.

### Слой доступа к данным (`dao.TvDao`)

Класс инкапсулирует операции над таблицей `public.tv` с использованием `JdbcTemplate` и маппера `BeanPropertyRowMapper`:

* `initTable()` — автоматическое создание схемы `public` и таблицы `tv` при старте приложения, а также вставка начального набора данных при пустой таблице.
* `findAll()`, `findById(int id)` — выборка данных.
* `insert(Tv tv)`, `update(Tv tv)`, `delete(int id)` — модификация данных.
* `findByPriceLessThanEqual(double maxPrice)` — выборка по ценовому критерию.

### Контроллеры (`controllers`)

* **`HomeController`** — обрабатывает GET-запрос по пути `/` и возвращает шаблон `index.ftl`.


* **`TvController`** — маппинг `/tvs`:
* `GET /tvs` — передает в модель список всех телевизоров (`tv_list.ftl`).


* `GET /tvs/add` и `POST /tvs/add` — отображение формы и прием данных через `@Valid @ModelAttribute("tv") Tv tv` с проверкой ошибок в `BindingResult`.


* `GET /tvs/edit` и `POST /tvs/edit` — редактирование существующего объекта по переданному `id`.
* `GET /tvs/delete` и `POST /tvs/delete` — подтверждение и удаление записи.
* `GET /tvs/search` — фильтрация списка по параметру запроса `@RequestParam("maxPrice")`.

## 4. Сценарии работы веб-приложения

### 1. Главная страница (`/`)

Отображает интерактивное меню со ссылками на функциональные блоки приложения:

* **URL:** `http://localhost:8080/tv-web-app/`

* **Результат:** навигация по каталогу, добавление и поиск по бюджету.



### 2. Просмотр таблицы записей (`/tvs`)

* **URL:** `http://localhost:8080/tv-web-app/tvs`
* **Результат:** рендеринг таблицы всех строк базы данных с колонками `ID`, `Бренд`, `Модель`, `Экран`, `Диагональ`, `Цена` и ссылками для перехода к операциям редактирования и удаления.



### 3. Добавление записи с валидацией (`/tvs/add`)

* **Корректный ввод:** заполнение полей значениями (`Xiaomi`, `A2 43`, `LED`, `43.0`, `27990.00`) $\rightarrow$ редирект в каталог `/tvs`, запись сохранена в базе.
* **Некорректный ввод:** отправка формы с пустым полем бренда и отрицательной ценой (`-500`) $\rightarrow$ форма не отправляется в БД; под полями выводятся диагностические сообщения: *«Поле бренда не должно быть пустым»* и *«Цена должна быть больше нуля»*.



### 4. Поиск записей по критерию (`/tvs/search`)

* **URL:** `http://localhost:8080/tv-web-app/tvs/search?maxPrice=70000`

* **Результат:** отображаются только телевизоры с ценой $\le 70\,000$ рублей (например, модели Samsung и Sony), более дорогие модели отфильтровываются.
